## خطوات كل أسبوع

1. **اجرد الصندوق.** ابحث في `١- صندوق التصاميم الجديدة` عن الصور (`parentId = '1iMjyU0tiAvl3574K4xGA7xjHLrn8a8o6'`، غير المجلدات). إن كان فارغاً: اكتب تقريراً قصيراً «لا جديد» وانتهِ.
2. **انظر إلى كل تصميم.** نزّل معاينته من مجلد «معاينات» (اسمها `معاينة__<معرّف الملف>.jpg`، ووصفها اسم الأصل). إن لم توجد فنزّل الأصل. المحتوى يصل base64: فكّه بـ python إلى ملف صورة ثم اقرأه بأداة القراءة. إن حُفظت النتيجة في ملف لكبرها فاقرأ الملف بـ python.
3. **صنّف.** لكل تصميم: الهوية (جذور، إشراق، بذور، إثمار، سنابل، أو نشاط: ترياق، الملتقى الجامعي، رفاق الأنشطة، الأنشطة التربوية، الأكاديمية، أو هوية نشاط جديدة)، والنوع (`ann` إعلان، `daily` مقرر يومي، `comp` مسابقة، `thanks` تهنئة، `quote` عبارة، `social` قصص ومنشورات، `cover` أغلفة وجداول، `yt` يوتيوب). شعار جديد لهوية؟ احفظه.
4. **قرّر ما يُضاف.** القاعدة: كل قالب جديد يعمل بكل الهويات (يستعمل أسماء الألوان لا قيمها)، فلا تصنع قالباً لهوية واحدة. لا تكرر قالباً موجوداً؛ إن كان التصميم الجديد قريباً من قالب قائم فاذكر ذلك في التقرير بدل إضافته. وأضف ما يستحق: تخطيط جديد، زخرفة جديدة، نوع جديد. ولك أن تضيف قوالب من عندك مستوحاة من الهويات.
5. **اكتب الحزمة** في ملف `pack-YYYY-MM-DD.js` (الصيغة أدناه).
6. **جرّبها في المختبر** (انظر «المختبر»). لا ترفع حزمة فيها خطأ رسم أو تداخل نصوص. انظر إلى `_sheet.jpg` بعينك: هل التصميم جميل ويشبه روح الأصل؟
7. **ارفعها** إلى `٢- حزم القوالب` بأداة إنشاء الملفات: `textContent` = نص الحزمة، `contentMimeType` = `text/javascript`، و`disableConversionToGoogleType` = true.
8. **انقل التصاميم المعالجة** إلى `٣- تمت معالجتها` (تحديث الملف بـ `parentId`)، ومعاينتها معها.
9. **اكتب التقرير** في `٥- تقارير التطوير الأسبوعية` مستند Google باسم `تقرير YYYY-MM-DD`: ما وصل، وما أُضيف (اسم كل قالب ونوعه)، وما لم يُضف ولماذا، واقتراحات تطوير للأسبوع القادم. بالعربية، وبلا مصطلحات تقنية إلا عند الحاجة.

## صيغة الحزمة

```js
PACK({
  id: '2026-10-16',                 // تاريخ الحزمة
  note: 'قوالب من تصاميم الأسبوع',
  identities: [                      // اختياري: هوية نشاط جديدة
    { id: 'arwah', group: 'act', name: 'أرواح تتآلف', full: 'أرواح تتآلف', desc: 'وصف قصير',
      logoData: 'data:image/webp;base64,...',   // الشعار بخلفية شفافة، أطول ضلع 440، webp جودة 88
      c: { p, pd, pl, s, sd, sdd, a, a2, paper, warm, ink, muted, teal, tealL } }   // كل الألوان مطلوبة
  ],
  assets: [ { key: 'img_camp', data: 'data:image/webp;base64,...' } ],   // اختياري: صور للقوالب (اجعلها خفيفة)
  templates: [ { /* قالب كامل، كما في templates2.js */ } ]
});
```

- معرّف القالب يبدأ بـ `pk_` ثم وصفه، مثل `pk_ann_mountain`. معرّف بنفس اسم قالب قائم **يستبدله**، فلا تفعل ذلك إلا لإصلاح خطأ موثّق في التقرير.
- لا تستعمل `//` ولا `/*` داخل النصوص بين علامات التنصيص (مزلق في Apps Script). التعليقات خارج النصوص مقبولة.
- كل الحزمة ملف واحد قائم بذاته. لا تعتمد على حزمة سابقة.

## قواعد الرسم

- **المقياس:** `const C = T.c, u = W / 1080, sv = svOf(W, H);` وكل الأبعاد مضروبة في `u` أو `sv`. للعناوين اضرب الحجم في `k` (منزلق حجم العنوان).
- **الخلفية:** `const base = OV.bg || C.paper; paintBg(ctx, W, H, base);` واحترم دائماً `OV.bg` و`OV.title` و`OV.accent` (ألوان المستخدم). لون النص على أي خلفية: `onBg(base, C.ink)`، و`isDark(base)`.
- **المجموعات:** قبل كل جزء قابل للتحريك أو الإخفاء: `G(ctx, 'title')`، والأسماء المعروفة: `logo title sub info date footer deco photo top card chip body ring name kicker shape panel who intro band quote list head rows boxes cta count tag`.
- **الزخارف:** داخل `if (D()) { ... }` لأن المستخدم قد يخفيها. والخلفيات الزخرفية الكبيرة داخل `quiet(function () { ... })` حتى لا تُحسب في فحص التداخل، ثم سجّل حدودها بـ `area(x0, y0, x1, y1)`.
- **النصوص:** لا تكتب `fillText` مباشرة. استعمل:
  - `const f = fit(ctx, str, { maxW, maxH, size, lh, balance: true, bold: 0..1, title: true, maxLines })` ثم `drawFit(ctx, f, x, y, { align: 'right'|'center'|'left', color, hl })`. ‏`y` أعلى النص، و`f.h` ارتفاعه، و`f.w` عرض أطول سطر. ما بين `*نجمتين*` يُلوَّن بـ `hl`.
  - `line(ctx, str, x, yCenter, { size, color, align, bold, maxW })` لسطر واحد، تعيد `{w}`.
  - `infoItem(ctx, icon, str, xRight, yCenter, { size, color, iconColor, maxW })` أيقونة ونص، تعيد العرض. و`infoW(...)` للقياس فقط.
  - `pill(ctx, str, xRight, yCenter, size, fill, color, { icon, dot, bold })` وسم.
  - النص العربي يُحاذى يميناً عادة: `xr = W - 80 * u`.
- **الشعارات:** `drawLogo(ctx, T, x, y, w, 'color' | '#ffffff', 'tr'|'tl'|'br'|'bl'|'tc'|'c')` تعيد `{w, h}`. ‏`academy(ctx, color, x, y, w, anchor)` و`social(...)`.
- **رسومات جاهزة:** `petal star sparkle chevrons xmark ribbonS pixelCards pine forestRow mountains nightSky tent campfire confetti band icon fillRR rrect hline vline drawPhoto`، والألوان: `alpha(hex, a)` و`lighten(hex, -1..1)` و`mixC(a, b, t)`. والأيقونات: `moon layers mic clock cal pin star link down up ring book`.
- **الصور:** حقل `kind: 'image'` يصل في `P[key]` بالشكل `{im, z, ox, oy}`؛ ارسمه بـ `drawPhoto(ctx, P.photo.im, x, y, w, h, { z: P.photo.z, ox: P.photo.ox, oy: P.photo.oy, fit: 'cover'|'contain' })`.
- اقرأ قالباً أو قالبين في `templates2.js` قبل الكتابة، وقلّدهما.

## أين الموقع

- الواجهة منشورة على GitHub Pages من المستودع `GHamine23/media-portal`، والمجلد `docs/` يُبنى من `src/`:
  https://ghamine23.github.io/media-portal/
- الخادم (الحسابات والقوالب المحفوظة والحزم) على Apps Script، ورابطه في `src/api_url.txt`.
- مجلدا درايف «٠» و«٦» أرشيف قديم لم يعد الموقع يقرأ منهما.
- الحزم الأسبوعية تبقى في درايف «٢- حزم القوالب»، ويقرؤها الموقع عبر الخادم ويحفظها في المتصفح. فالحزمة لا تحتاج أي تعديل في المستودع.

## المختبر

1. أضف المستودع إلى الجلسة بأداة إضافة المستودعات بصلاحية الدفع (push)، ثم استنسخه.
2. ثبّت ما يلزم إن غاب: `pip install playwright pillow --break-system-packages` (المتصفح مثبّت مسبقاً عادةً).
3. شغّل من جذر المستودع: `python3 src/lab/lab_test.py src pack-YYYY-MM-DD.js out`
4. أصلح كل «خطأ رسم» وكل «تداخل» ثم أعد التشغيل. ثم انظر إلى `out/_sheet.jpg`.
5. لتجربة الموقع كاملاً بالأصول الحقيقية: ضع الحزمة في مجلد `packs_local/` في جذر المستودع (لا يُرفع)، وشغّل `python3 src/build.py`، ثم افتح `dist/index.html` بالمتصفح الآلي.

الشعارات والخطوط في المختبر بدائل (مستطيلات وخط النظام)، فالمعتبر المواضع والتداخل.

## تعديل ملفات الموقع الأساسية

الأصل أن يكون التطوير بالحزم. إن احتجت إصلاح خطأ أو تحسيناً في الواجهة أو المحرك:
1. عدّل في `src/`، ثم شغّل `python3 src/build.py` (يبني `docs/`)، وجرّب `dist/index.html` بالمتصفح الآلي: الرئيسية وقالب والمحرر والشرائح، بلا أخطاء في الطرفية.
2. التزم (commit) برسالة عربية واضحة وادفع إلى `main`، فيتحدّث الموقع خلال دقائق. التراجع ممكن دائماً من تاريخ المستودع؛ اذكر رقم الالتزام في التقرير.
3. لا تغيّر `src/Code.gs` (يحتاج لصقاً يدوياً في Apps Script)، واكتب ما تقترحه فيه في التقرير.

## ما لا تفعله أبداً

- لا تحذف أي تصميم أو ملف؛ النقل فقط.
- لا تلمس `٤- بيانات الموقع`.
- لا تضغط الصور أو الشعارات أو الخطوط ولا تصغّرها لتسريع الموقع ولا لأي سبب. أي تنازل عن الجودة يُعرض على أمين أولاً في التقرير (قراره الصريح).
- لا تضع صور طلاب في القوالب.
- لا تنسخ ألوان هوية في قالب عام؛ استعمل `T.c`.
